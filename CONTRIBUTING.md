# Beitragsrichtlinie / Contributing Guide

## Deutsch

Vielen Dank für dein Interesse an `ellmos-plugins`! Dieses Repository bildet
den Claude-Code-Plugin-Marktplatz des **ellmos**-Ökosystems (`ellmos-ai`).

### Grundregeln für Änderungen

1. **`plugins/` niemals direkt von Hand bearbeiten:** Die Ordner unter
   `plugins/` (z. B. `plugins/ellmos-dev-quality`, `plugins/ellmos-decision-kit`,
   `plugins/ellmos-mermaid-lint`) werden durch `tools/build.py` aus
   `catalog.json` und [ellmos-ai/skills](https://github.com/ellmos-ai/skills)
   generiert. Inhaltliche Skill-Änderungen gehören in `ellmos-ai/skills` oder
   `catalog.json`, gefolgt von `python tools/build.py --skills-repo <Pfad>`.
2. **Pin-Governance für sicherheitskritische Plugins:** Plugins wie
   `ellmos-lock-master` dürfen nicht auf veränderlichen Branches schweben. Jede
   Pin-Aktualisierung erfordert den vollständigen 5-stufigen Gate-Prozess aus
   `README_de.md` / `README.md` (annotierter Tag, adversariales `--plugin-dir`-Gate,
   Manifest-Regenerierung + `claude plugin validate .`, unabhängiges PR-Review,
   anschließender Live-Marketplace-Check).
3. **Eval-Suites getrennt halten:** Eval-Suites mit Shell-Skripten gehören
   nach `evals/<plugin>/`, nicht in `plugins/` (Ausnahme: bereits eingereichte
   reine Markdown-Evals in `plugins/ellmos-decision-kit/evals/`).

### Pull-Request-Ablauf

1. Forke das Repository oder erstelle einen Feature-Branch (`git checkout -b chore/mein-thema`).
2. Prüfe Änderungen lokal:
   - `ruff check .`
   - `python -m compileall -q tools tests`
   - `pytest -ra -v`
   - `claude plugin validate .` (sofern die Claude Code CLI verfügbar ist)
3. Reiche einen Pull Request gegen `main` ein.

### Code- & Dokumentationsrichtlinien

- Python >= 3.10, UTF-8, `ruff`-konform
- Zweisprachige Pflege (EN/DE) bei Root-Governance- und Einstiegsdokumenten;
  echte deutsche Umlaute (`ä ö ü ß`) verwenden
- Keine hartkodierten lokalen Pfade, Credentials oder interne Logs (`*MARKETING-LOG.txt`)

## English

Thank you for contributing to `ellmos-plugins`! This repository hosts the
Claude Code plugin marketplace for the **ellmos** ecosystem (`ellmos-ai`).

### Core Contribution Rules

1. **Never edit `plugins/` by hand:** Directories under `plugins/`
   (`ellmos-dev-quality`, `ellmos-decision-kit`, `ellmos-mermaid-lint`) are
   generated by `tools/build.py` from `catalog.json` and
   [ellmos-ai/skills](https://github.com/ellmos-ai/skills). Edit skills in
   `ellmos-ai/skills` or update `catalog.json`, then run
   `python tools/build.py --skills-repo <path>`.
2. **Pin governance for security plugins:** Security-critical plugins such as
   `ellmos-lock-master` must stay pinned to an annotated tag (`ref`) and exact
   commit SHA (`sha`). Pin updates must follow the 5-step gate in `README.md`.
3. **Keep shell-based eval suites in `evals/`:** Suites with scaffold shell
   scripts live under `evals/<plugin>/` rather than inside `plugins/`.

### Pull Request Workflow

1. Fork the repository or create a feature branch (`git checkout -b chore/my-change`).
2. Run local verification before opening a PR:
   - `ruff check .`
   - `python -m compileall -q tools tests`
   - `pytest -ra -v`
   - `claude plugin validate .` (when Claude Code CLI is installed)
3. Open a pull request against `main`.

### Code & Documentation Guidelines

- Python >= 3.10, UTF-8, clean under `ruff`
- Keep root governance and overview docs aligned in EN and DE
- Never commit hardcoded local host paths, secrets, or internal logs (`*MARKETING-LOG.txt`)
